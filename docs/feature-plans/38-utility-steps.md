# F38 — Utility steps

Status: implemented and locally qualified on 2026-10-20. One feature PR; no F21/F22 work.

## Decisions

Follow [n8n XML](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.xml/), [HTML](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.html/) and [Crypto](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.crypto/), and [Zapier Formatter](https://help.zapier.com/hc/en-us/articles/8496212590093-Get-started-with-Formatter): ordinary mapped data in, ordinary JSON out. Six v1 transform definitions: XML, Extract HTML, Crypto, HMAC, Text and Format number. All safe to repeat; random outputs deliberately change when executed again. No document fetching, provider requests, expression evaluation, new service, role or engine path; HMAC only uses the existing internal credential resolution capability.

- Preserve the SDK's 1 MiB whole-invocation envelope and the existing stricter **256 KiB retained JSON output**, depth 64 and 10,000-member bounds and the shared 4,998-item collection cap. Operations fail with static, content-free messages when their result is too large; never truncate silently. Check cancellation. All inputs are mapped through the usual Inputs controls; config holds choices only.
- **XML:** parse strictly with pinned `@rgrove/parse-xml` (no dependencies, no external/custom entity resolution) and build with pinned `fast-xml-builder`’s public XMLBuilder. A bounded htmlparser2 event preflight protects the strict parser’s recursive reader before it allocates the tree. The strict parser handles XML characters/entities without custom decoding. Values stay strings, attributes use `@_`, text uses `#text`, repeated siblings become arrays. Preserve namespace prefixes. Ignore declarations and processing instructions; comments are not data. This is a data conversion, not a lossless mixed-content/document formatter. Normalize source line endings once per XML 1.0 §2.11 before parsing (also avoiding quadratic repeated-CR normalization in the parser); numeric CR references stay unchanged. Built-in/numeric entities are decoded without custom expansion; reject DTD declarations/custom entities and dangerous object keys. Limit depth and elements/attributes before JSON construction. Build one root object; preflight tag repetition, entity expansion, depth and member count before the builder allocates output. Validate names, quote boolean attributes, omit null attributes and require non-null scalar #text; anonymous nested lists need named children. Escape values, then validate the resulting XML. Reject unsupported structures clearly. No file/network resolution, XSLT or schema loading.
- **HTML:** pinned `htmlparser2`, `domhandler`, `domutils`, `css-select` and `css-what` parse inert text and select text or one named attribute. Return `{items: string[], matchCount, truncated}` in document order (missing attributes are empty strings), with a configurable result limit up to 4,998 and explicit truncation metadata. DOM depth at most 48 and 8,000 nodes including attributes/text. Selectors at most 256 characters, four groups and 16 total tokens: tags, classes, IDs, attributes, child/adjacent combinators and at most one descendant and one structural pseudo per group; flat structural pseudo-classes (root/empty, first/last/only/nth child or of-type); no general sibling (~), pseudo-elements, relational/content pseudos or nested selectors. A maximum-depth repeated-descendant qualification stalled even with the library’s cache enabled; this bounded subset rejects that work before querying rather than adding another execution runtime. These deliberate limits avoid expensive selector recursion. Use parser callbacks to enforce DOM limits during construction. Never fetch URLs, execute scripts, return raw markup or render extracted values as HTML.
- **Crypto:** SHA-256, SHA-512 and MD5 over exact UTF-8 text, hex or base64. MD5 is explicitly labelled **not for security**. UUID v4 and random IDs use Node's cryptographic RNG; random IDs are 1–256 URL-safe characters (default 24), with no seeded or predictable mode. No password hashing/encryption/key generation feature.
- **HMAC:** SHA-256/512, hex/base64 over exact mapped UTF-8 text. Use a new **Signing key** profile in the existing encrypted connections area (`signing`/`hmac_key`), not plaintext settings, input data or expressions. The key is exact UTF-8, 1–4,096 bytes, never trimmed; one browser-safe SDK schema owns it as `signingKey`, a name already covered by the logging redaction owner. Existing workspace access, rotation, encryption, redaction and audit paths apply. Resolve and assert the current secret through the existing worker capability, zero owned byte buffers, and return only the signature. Testing this connection verifies it can be opened locally, with no external authentication claim. Workspace variables remain non-secret; no new secret-variable mode is introduced.
- **Text:** upper/lower case (explicit en-US Unicode casing), trim, literal replace (first/all; never regex), split on a nonempty literal delimiter and truncate by Unicode code points with optional ellipsis inside the chosen limit. Search/replacement/delimiter are mapped values. Split/truncate limits are explicit; reject output overflow before expensive allocation.
- **Number:** `Intl.NumberFormat` with an explicit locale (en-US default; de-DE, fr-FR, en-GB, ja-JP), decimal/percent/currency, grouping and 0–20 fractional digits. Currency is an ISO-style uppercase three-letter code. Accept finite numbers; no implicit text parsing, exchange rates or machine-locale inference.
