# F34 — Create file

Status: implemented and locally qualified on 2026-10-20; delivery PR pending CI. F45 remains separate.

## Decisions and rules

Like [n8n Convert to File](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.converttofile), a transform takes mapped data and returns a reusable file. One `core.create_file` v1 definition, three formats: CSV, JSON, text. No spreadsheet dependency, new service, role, table or stored artifact format.

- Input is `{data: <mapped value>}`. JSON accepts any bounded JSON value and writes compact UTF-8 JSON. Text requires a string and writes exact UTF-8 (no implicit stringify). CSV requires an array of objects, up to the shared 4,998 collection cap, within the existing whole-invocation envelope. The config/input wrapper leaves about 4,996 narrow rows with automatic columns; explicit names or wide rows leave fewer.
- CSV always writes a header and CRLF records. Comma, semicolon or tab delimiter. Optional ordered column names select the output; an empty selection uses the union of row keys in first-seen order, within the existing 4,998-item collection cap and whole-invocation bounds. Explicit column names are unique, nonblank, at most 256 characters; missing cells are empty. Nested values use compact JSON, null/absent cells are empty. Empty rows need explicit columns so the header is meaningful.
- Use the existing CSV escaping and spreadsheet-formula protection for both headings and cells; move that function from the data-table area to the SDK's values area in a separate behavior-preserving commit, with deliberate generic naming. No duplicate CSV escaping policy.
- Output is `{file: {kind:'artifact',artifactId,byteLength,mediaType,sha256}}`, the existing F04 reference. MIME types are text/csv, application/json and text/plain with UTF-8. Filenames remain a destination/download concern; multipart already allows one.
- Generated bytes, including CSV quoting and headers, must fit 1 MiB. Count actual UTF-8 bytes before calling the worker writer; fail with a content-free code and split-file advice. Existing input byte/depth/member bounds remain. Never put file contents in diagnostics.
- The existing worker artifact write capability handles spooling, checksums, finalize, capacity, attempt identity and cleanup; pass the 1 MiB ceiling. Existing preview/test/run retention, reference visibility, download authorization and redaction rules apply. Safe retry class: it changes nothing outside Pertexo; operational writer failures use the existing bounded safe retries and a content-free storage/usage diagnostic. Missing storage configuration and malformed data fail definitely. Abandoned attempt artifacts expire through the existing lifecycle.
- A real destination is never called for creation. Subsequent HTTP uploads retain ordinary effects warnings. No special recovery rule.

## Ownership and delivery

1. Separate move-only commit for the shared CSV escaping function and imports, after this plan is recorded.
2. `packages/nodes-core/src/data/create-file/`: schemas, manifest, encoder and executor. Register through the existing core catalog/registry; `artifact_output` capability, ordinary safe IO step.
3. Web: catalog name/icon, starting settings and a small inspector builder for format, delimiter and ordered column names. Use normal mapped Inputs; no browser file parsing/generation or new state owner. The shared setup scratch tracker covers both fields and JSON so incomplete column names cannot be discarded by a format/mode switch.
4. Extend `docs/guides/files.md`, F04's later-work claims and the roadmap. Validate encoding/bounds/errors, catalog portability and editor behavior. Qualify creation through the real worker writer, checked Read file and local multipart receiver; preserve retention and foreign/fingerprint rejection tests.
5. Full lint/type/unit/pre-push, mocked editor at desktop/phone, React Doctor and green CI; rebase-merge.

## Verification

Workspace check (build, lint, types, contracts, schema, boundaries) passes. Core: 268 tests; catalog: 1,244; web: 1,429; mocked browser: 275, including both themes at 375/990/1440 px. Real worker qualification creates CSV through the artifact writer, reads, filters and summarizes it, then sends exact multipart bytes to a local receiver; workspace/fingerprint checks and expiry are asserted. The whole-invocation maximum of 4,996 narrow rows produces 24,990 bytes in about 9–11 ms on the development machine. Exact 1 MiB encoded output is accepted and one extra byte is refused before storage. React Doctor: 98/100 with no changed-code findings. Full pre-push and remote CI gate delivery.
